# 5. Сбалансированность ролей

Требование ТЗ: ни один агент не выполняет больше 40% всех вызовов LLM и инструментов
в типовом сценарии, и это подтверждается логами.

## Как считается

Каждый вызов LLM (`llm_call`) и каждый вызов инструмента (`tool_call`) пишется в
`runs/<task_id>/log.jsonl` с именем агента. Доля агента = (его вызовы LLM + вызовы инструментов) / все вызовы.
Отчёт печатается после каждого запуска `main.py`, сохраняется в `runs/<task_id>/load_report.json`
и пересчитывается по логу командой:

```bash
python scripts/load_report.py runs/<task_id>/log.jsonl
```

## Проектная оценка для полной системы (типовой сценарий)

Сценарий: *«Можно ли завтра утром бегать в Алматы?»* (intent=health, все 7 агентов).

| Агент | Вызовы LLM | Вызовы инструментов | Всего | Доля |
|---|---:|---:|---:|---:|
| Orchestrator | 2 (план + решение по вердикту) | 0 | 2 | 8% |
| Data Agent | 3 | 3 (geocode, air ∥ weather) | 6 | 23% |
| Forecast Agent | 2 | 2 (ML ∥ CAMS) | 4 | 15% |
| Analyst Agent | 2 | 3 | 5 | 19% |
| Health Agent | 2 | 2 | 4 | 15% |
| Reporter Agent | 1 | 0 | 1 | 4% |
| Critic Agent | 2 | 2 | 4 | 15% |
| **Итого** | 14 | 12 | **26** | max **23%** |

Худший типовой случай: город не найден с первого раза и критик один раз вернул ответ на доработку.
Тогда получается 34 вызова, а у самого загруженного агента (Data Agent) 8 вызовов, то есть 24%.
Запас до 40% большой.

## Что удерживает баланс

1. **Узкие роли.** Data Agent только добывает данные, анализ отдан Analyst Agent, а советы — Health Agent.
2. **Параллельные вызовы.** Независимые инструменты (`fetch_air_quality` ∥ `fetch_weather`,
   ML ∥ CAMS) вызываются в одном ходе LLM, поэтому на них уходит один вызов LLM, а не два.
3. **Числа считает код.** Агентам не нужны лишние ходы LLM на арифметику.
4. **План под запрос.** Для `current` не запускаются Forecast и Health, а для `explain` — Health.
5. **Лимиты.** `MAX_AGENT_STEPS=6` не даёт одному агенту «раздуться».

## Фактические замеры прототипа (Ассайнмент 2)

В прототипе реализованы только 3 из 7 агентов, поэтому доли пока не показательны:
те же вызовы делятся на троих. Реальный прогон (Gemini 3.5 Flash, «Можно ли послезавтра
гулять с ребёнком в Нур-Султане?», лог `examples/run_health_astana/log.jsonl`):

| Агент | LLM | Инструменты | Всего | Доля |
|---|---:|---:|---:|---:|
| data_agent | 3 | 3 | 6 | 55% |
| forecast_agent | 2 | 2 | 4 | 36% |
| orchestrator | 1 | 0 | 1 | 9% |

Фактическое число вызовов каждого агента совпало с проектной оценкой: 6 у Data Agent, 4 у Forecast
Agent, 1 у Orchestrator (второй вызов Orchestrator'а появится вместе с Critic Agent). Значит,
после добавления Analyst, Health, Reporter и Critic в Ассайнменте 4 доля Data Agent опустится
примерно до 23%, и это будет подтверждено логами типового сценария.
